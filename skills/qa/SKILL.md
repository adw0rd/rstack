## Runtime rcode

Скилл — руководство, а не разрешение. Используй реальные инструменты rcode; вопросы пользователю задавай обычным текстом. В plan/read-only не вызывай shell или запись: явно укажи непроведённые проверки. Не переключай провайдера и не вызывай внешнюю модель без выбора пользователя. Не читай и не выводи ключи. Не выдумывай supporting files: используй только имена из resources ответа load_skill.

Цель — проверить конкретный пользовательский сценарий проекта и, при нахождении бага, довести его до подтверждённого исправления с регрессией. Не публиковать без явного запроса; авто-коммитов нет.

## Подготовка

- Выбрать наблюдаемый сценарий и ожидаемый эффект (что видит пользователь / что должно появиться в файле / какой exit code).
- Изолировать данные и настройки: временный каталог, отдельный home, явный набор env. Не трогать живые данные пользователя.
- Не имитировать живые API фикстурами, выдавая их за живую проверку: явно отделять «живой прогон» и «фикстура» в отчёте.

## Проверка (не только модель)

- Ответ модели — не единственный сигнал. Проверить: файлы, которые должны создаться/измениться; exit code процесса; результат конкретного инструмента (write_file, run_command, search).
- Зафиксировать реальную команду и её вывод. Не называть пройденным то, что не запускалось.

## Если баг найден

1. Воспроизвести: минимальный набор команд, детерминированно дающий ошибку.
2. Использовать существующий тест, который воспроизводит баг, или добавить регрессионный тест при пробеле покрытия. Доказать FAIL на текущем состоянии (RED), сохранить вывод; не дублировать уже достаточную проверку.
3. Найти корневую причину (при необходимости загрузи rstack:investigate).
4. Исправить корень, а не симптом; не ослаблять корректный существующий тест ради GREEN.
5. Доказать GREEN: регрессионный тест проходит, исходный сценарий проходит, соседний happy path не сломался.

## Итог

Отчёт: сценарий, изоляция, наблюдаемый результат, баг (если есть), RED/GREEN с реальными выводами, что осталось. Если не удалось проверить часть — так и написать, без «вероятно работает».
