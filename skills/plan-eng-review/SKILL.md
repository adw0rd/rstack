# Инженерное ревью плана

Результат: Исполнимый инженерный план с контрактами и порядком проверки.

## Runtime rcode

Инструменты: `read_file`, `search`, `list_files`; запись — `write_file`/`edit_file`, shell — `run_command`/`start_command`, план — `update_plan`. В `/plan` и ролях `explorer`/`reviewer` нет shell и записи; субагенты (`explorer`/`reviewer`/`worker`) не имеют `ask_user`, памяти и `load_skill` (`wait_agent`).

Скилл не выдаёт прав: соблюдай подтверждения rcode и opt-in ОС-песочницу (`--sandbox`, `/sandbox`; в `--sandbox read-only` разрешённый shell пишет лишь в приватный `TMPDIR`), hooks нет. Публикация и внешний LLM/API требуют выбора без fallback. Ключи не передавай в args, историю, логи, память и shell; на `localhost`/`127.0.0.1`/`[::1]` бери заглушки без секретных присваиваний, PEM, префиксов (`sk-`, `ghp_`) и `user:pass@`.

Поиск/HTTP — `web_search`/`web_fetch` (не браузер). Развилки вне файлов в интерактиве основного агента уточняй через `ask_user` (1–3 вопроса, 2–4 варианта, 1-й рекомендуемый, без повтора, не права/секреты), в `exec`/без TTY — текстом. `read_memory` — историческая справка (сверяй с файлами); `write_memory` — только интерактивному основному агенту вне `/plan` для `[stated]` решений без секретов (иначе выведи текстом).

## Условия

Достаточно доступных инструментов rcode и файлов проекта; нужные команды проверок обнаруживаются в самом проекте.

## Порядок работы

1. Сначала `list_files` root и чтение README/индекса. До DRAFT прочитай авторитетные контракты, затронутую реализацию и команды проверок (без индекса — список+один ограниченный поиск; ненайденное = unknown), затем план и ссылки. Proposal не доказывает поведение.
2. DRAFT-таблица: риск/контрпример → владелец (caller/dependency) → гарантия/предусловие+цитата → правка/тест той же обязанности. Советы: necessary-in-scope/optional/out-of-scope; новая гарантия отдельно от текущей. Команды из источника или unknown; в проект не пиши.
3. До reviewer выбери проверяемый существенный claim DRAFT, прочитай API/тесты, исключи побочные эффекты вне пробы (вне проекта и процессы без песочницы; в `--sandbox read-only` запись только в приватный `TMPDIR`) и запиши ожидание до запуска. Только при разрешённом `run_command` и локальном probe без записи в проект, сети и установки выполни один probe через существующий API (пометь новой пробой, не готовым тестом); сверь receipt и исправь DRAFT при опровержении. Иначе/при сбое — untested (контрпример и план без обхода ограничений). Зелёный suite не доказывает claim; в stub проверяй наблюдаемое, не переноси на несимулируемые свойства.
4. Без контракта/цитаты или DRAFT — partial/blocked, reviewer не запускай. Иначе вызови ровно один `spawn_agent` (`role: reviewer`, тот же провайдер, без provider/model; поля только `task`, `name`, `role`, `task` ≤16000 симв.) с 4 секциями с новой строки: `SOURCE_PATHS` — точные пути; `CONTRACT_QUOTES` — краткие цитаты с путями; `DRAFT` — советы, проверки и probe (ожидание/команда/receipt/вывод); `REVIEW_QUESTION` — «Сверь DRAFT с цитатами и чтением; верни противоречие → цитату/путь → контрпример → исправление/unknown». Reviewer читает сам (read/search/list, без shell, записи, `load_skill`, памяти и делегирования).
5. По `agent_id` вызови `wait_agent`: нужен `status: completed` (ошибка/отмена/иной статус/непрочитанный источник — partial/blocked, второго reviewer не запускай).
6. Сверь свои и reviewer выводы с цитатами: исправь, отклони с причиной или unknown. Blocker — только necessary-in-scope с причиной; optional/out-of-scope не блокируют; `completed` не PASS/разрешение. Итог: probe/receipt, решения пользователя, unknown, шаг. Мысленный прогон — не запуск.

## Обязательный чеклист результата

- Родитель процитировал контракт; один reviewer сам прочитал источники, родитель дождался `status: completed` и сверил вывод с цитатами/контрпримером. Без контракта или DRAFT независимое ревью не заявлено.
- Один существенный claim имеет ожидание до запуска, receipt и вывод для reviewer; ошибка/невозможность помечена untested. В stub проверяется только наблюдаемое; вывод не переносится на несимулируемые свойства.
- Контракт/proposal/advice разделены; тест проверяет обязанность владельца; blocker нужен в scope. Решения пользователя и разрешения сохранены.

## Материалы и завершение

Вход самодостаточен. Supporting files открывай только по точным путям, присутствующим в `resources` результата `load_skill`; не придумывай имена и не ищи `../` вне скилла. При усечении продолжай по возвращённому `next_line` с тем же `sha256`.

Обязательный чеклист приведён выше; [развёрнутые критерии и сценарии](references/acceptance.md) — дополнительная справка. [Происхождение](references/upstream.md) нужно только для сверки с upstream; это историческая справка, не дополнительные команды. Не загружай все материалы без причины.

Укажи выполненное, доказательства, оставшееся и блокеры. Для блокера назови недостающее предусловие и один выполнимый следующий шаг; не повторяй одинаковый preflight. Отделяй проверенное от `blocked`/`untested`.
