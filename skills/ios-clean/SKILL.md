# Удалить принадлежащий QA DebugBridge

Результат: Проверенная очистка конкретных debug-артефактов с возможностью восстановления.

## Runtime rcode

Инструменты: `read_file`, `search`, `list_files`; запись — `write_file`/`edit_file`, shell — `run_command`/`start_command`, план — `update_plan`. В `/plan` и ролях `explorer`/`reviewer` нет shell и записи; субагенты (`explorer`/`reviewer`/`worker`) не имеют `ask_user`, памяти и `load_skill` (`wait_agent`).

Скилл не выдаёт прав: соблюдай подтверждения rcode и opt-in ОС-песочницу (`--sandbox`, `/sandbox`; в `--sandbox read-only` разрешённый shell пишет лишь в приватный `TMPDIR`), hooks нет. Публикация и внешний LLM/API требуют выбора без fallback. Ключи не передавай в args, историю, логи, память и shell; на `localhost`/`127.0.0.1`/`[::1]` бери заглушки без секретных присваиваний, PEM, префиксов (`sk-`, `ghp_`) и `user:pass@`.

Поиск/HTTP — `web_search`/`web_fetch` (не браузер). Развилки вне файлов в интерактиве основного агента уточняй через `ask_user` (1–3 вопроса, 2–4 варианта, 1-й рекомендуемый, без повтора, не права/секреты), в `exec`/без TTY — текстом. `read_memory` — историческая справка (сверяй с файлами); `write_memory` — только интерактивному основному агенту вне `/plan` для `[stated]` решений без секретов (иначе выведи текстом).

## Условия

Нужны macOS, Xcode, исходники приложения, выбранное доверенное iOS-устройство и уже установленный companion bridge/daemon. Проверяй фактический CLI help, подключение и Debug-конфигурацию до изменения приложения; без них не объявляй device-проверку выполненной.

- Доступны manifest/markers созданного DebugBridge и реальные build-команды; runtime нужен для подтверждения закрытия daemon/device listener.

## Порядок работы

1. Инвентаризируй DebugBridge, generated accessors, build hooks, debug token и companion state по manifest/codegen markers.
2. Покажи точный список принадлежащих QA артефактов и существующие локальные изменения; не удаляй одноимённые business-компоненты.
3. Удаления требуют подтверждения приложения даже в full-access; не обходи его скриптом.
4. Удали только подтверждённые generated файлы и точечные интеграционные участки, оставляя обычное состояние приложения.
5. Собери Debug и Release штатными командами и проверь отсутствие debug listeners/bridge symbols в Release.
6. Для собственных daemon/tunnels проверь terminal status и закрытые порты; чужие процессы не трогай.
7. Запиши, как вернуть bridge штатной ios-sync/ios-qa процедурой, не восстанавливая старые токены.

## Обязательный чеклист результата

- Ни один пользовательский business-файл не потерян.
- Очистка подтверждена build и отсутствием принадлежащих задаче debug listeners.

## Материалы и завершение

Вход самодостаточен. Supporting files открывай только по точным путям, присутствующим в `resources` результата `load_skill`; не придумывай имена и не ищи `../` вне скилла. При усечении продолжай по возвращённому `next_line` с тем же `sha256`.

Обязательный чеклист приведён выше; [развёрнутые критерии и сценарии](references/acceptance.md) — дополнительная справка. [Происхождение](references/upstream.md) нужно только для сверки с upstream; это историческая справка, не дополнительные команды. Не загружай все материалы без причины.

Укажи выполненное, доказательства, оставшееся и блокеры. Для блокера назови недостающее предусловие и один выполнимый следующий шаг; не повторяй одинаковый preflight. Отделяй проверенное от `blocked`/`untested`.
